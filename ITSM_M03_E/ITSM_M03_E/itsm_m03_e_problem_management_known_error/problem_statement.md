# ITSM Lab: Problem Management & Known Error Database (KEDB) Authoring - Recurring Memory Leak

Duration : 90 Min.

## Scenario
An application server experiences recurring memory exhaustion every 72 hours, resulting in repeated P3 incident tickets. Shift from reactive incident firefighting to proactive Problem Management. Create a Problem ticket, author a Known Error Database (KEDB) record with a verified temporary workaround (scheduled service recycle), document root cause hypothesis, and define criteria for permanent code remediation.

## Task Objectives
Perform the following actions inside the `student_workspace` directory:
- Recognize triggers for converting recurring incidents into a formal Problem record.
- Distinguish a temporary workaround from a permanent resolution.
- Author a structured Known Error record in the ServiceNow KEDB.
- Define criteria and link Problem record to a planned Normal Change RFC.

## Instructions to Perform the Task
1. When your workspace loads in **VS Code**, use the **Explorer** panel on the left to locate your files.
2. Navigate to and click the specific files mentioned in the Task Objectives.
3. Make the necessary code edits in the editor.
4. Press `Ctrl + S` (Windows) or `Cmd + S` (Mac) to save your changes.
5. If you need to run commands, open the built-in terminal by clicking **Terminal > New Terminal** from the top menu.

## Validation
Once you have saved your files and are ready to submit, return to the platform dashboard and click the **"Submit Final"** button. This task is evaluated manually by the grading team.

## Evaluation Rubric:
1. Justified initiation of Problem record linking multiple historical incident occurrences: 3 marks
2. Formulation and validation of a safe, non-destructive temporary workaround: 3 marks
3. Authoring of a compliant Known Error record in the KEDB with symptoms, workaround, and root cause notes: 2 marks
4. Formal linkage of Problem ticket to a planned Request for Change (RFC) for permanent fix: 2 marks

**Total Score: 10 Marks**
